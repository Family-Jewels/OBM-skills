# OBM reference for the swarm skills

The skills are written for agents: short, imperative, priorities first. The reasoning behind them lives here, for people.

## Where each rule comes from

| Rule in the skills | Source |
| --- | --- |
| Fix the environment before blaming the performer; check information, resources and incentives first | Gilbert (1978), the Behavior Engineering Model |
| Judge on value delivered for its cost | Gilbert, worthy performance |
| Name products, not activities | Gilbert, accomplishment vs behavior; Daniels, pinpointing |
| Map stages and own every handoff | Rummler & Brache, behavioral systems analysis |
| Ask whether a check can be passed without the goal | Kerr (1975), "On the folly of rewarding A, while hoping for B" |
| Consequences immediate, certain and identical every time | Daniels, PIC/NIC analysis |
| Rules state "if, then, because", within a budget | Malott (1992), rule-governed behavior |
| Specific, criterion-referenced feedback | Alvero, Bucklin & Austin (2001) |
| Diagnose antecedents, equipment, knowledge and consequences | Austin (2000), the Performance Diagnostic Checklist |
| Report must match the artifact | Risley & Hart (1968), say-do correspondence |
| The auditor re-verifies a hidden sample | Interobserver agreement |
| Thin review as reliability is shown | Ferster & Skinner (1957), schedule thinning |
| Activity rising without results signals trouble | Lerman & Iwata (1995), extinction bursts |
| Act on signals, not routine variation | Deming; Wheeler, *Understanding Variation* |
| The receiving system selects the product; the human manages rules | Glenn (1988), metacontingencies |
| Managers need contingencies too | Malott, managing the managers |
| The system, not the agents, runs the review cadence | This project's long-horizon runs: written instructions to call other roles faded within days |
| Never pause the core work to fix records | This project's runs: an audit that did so brought output to zero |

## Glossary: OBM term to swarm practice

| OBM term | Swarm practice |
| --- | --- |
| Worthy performance (Gilbert) | Value of the accomplishment divided by its cost; judge the swarm on both |
| Accomplishment vs behavior (Gilbert) | Specs name products, not activities |
| Pinpointing (Daniels) | Every task has an observable product and checkable criteria |
| Behavioral systems analysis (Rummler-Brache) | Process map with every handoff owned |
| White space | The handoffs between roles |
| Task clarification and job aids | Briefs, templates, output schemas |
| Performance feedback (Alvero et al.) | Specific, criterion-referenced, immediate review records |
| PIC/NIC analysis (Daniels) | Check that desired outcomes are positive, immediate and certain |
| Shaping | Milestones and small reinforced units |
| Schedule thinning | Full to sampled review as reliability holds |
| Extinction burst | Repeated failures turning into erratic or rule-breaking actions |
| Say-do correspondence (Risley & Hart) | Report-reality agreement |
| Interobserver agreement | Auditor re-verification of a hidden sample |
| Metacontingency (Glenn) | Interlocking agent contingencies producing one selected product |
| Performance Diagnostic Checklist (Austin) | The diagnostician's question set |
| Process behavior chart (Deming, Wheeler) | Scorecard signals: common vs special cause |
| Behavior-based safety | No-blame block and near-miss reporting |
| Managing the managers (Malott) | The auditor audits the orchestrator |
| Risk-based inspection (quality management) | Review depth set by risk tier |
| Exemplary standard (Gilbert) | "Good enough for the goal," not the most achievable |
| Antecedent control | The index, notes and briefs agents read before acting; audited because a wrong record misdirects everyone after it |
| Rule-governed behavior (Malott) | Rules state purpose and contingency, within a budget, because long or bare rules are followed poorly |
