The orchestrator's `Applied` line in E-003 and its log (`swarm/log/progress.md`, D113, D128, D139) were read only to know what to look for. They are not evidence.

The comparison as specified is the day-142 snapshot against the one before Start (day 113). **That snapshot is not in the set.** `swarm/snapshots/` holds 00122 to 00144 only; `00112.md` and `00113.md` return "does not exist" (a glob for `0011*` finds nothing). Experiment file: `swarm/experiments/E-003.md`. Slice: AI-LOUNGE (DRINKS and SNACK, both machines). Control: AI-HOUSE and MAIN-LOUNGE. Change: a stocked slot on the slice is filled from depot stock even when the slot snapshot predicts no sales; each fill priced the same day; duplicate-slot sharing unchanged; no other change on the slice.

## Checks and results

1. **Change on every unit of the slice: not verified.**
   - The 00142 slot table has price, quantity, unit cost and loaded day per slot, and a storage table, an order table and a marketing table. No column or section carries a fill rule, per slot or per machine. The schema is the same as in F-E-003-1 (day 114) and F-E-003-2 (day 131).
   - The AI-LOUNGE slots show stock and recent loads (for example DRINKS A1 cola loaded 137, A2 oat loaded 137, SNACK A2 gummy loaded 138), which shows stock moved onto the slice. It cannot show that the always-fill change, rather than the default predicted-sellers rule, governed each unit. The lever the change uses is not covered by the snapshot.
   - Also empty on AI-LOUNGE at day 142 with a product assigned: SNACK B1 mint-tin (mint in depot: none), SNACK C1 crisps (in slot, qty 0; depot has no crisps). Empty DRINKS B-C slots are not fills the change would have made if the depot lacked stock. Noted, not a criterion.

2. **No change on any unit outside the slice: met as far as the snapshot can show, but the same gap applies.**
   - AI-LOUNGE and control prices in 00142 match the standing set (AI-LOUNGE DRINKS 1.87, 2.75, 1.76; SNACK 2.2, 1.8, 2.2, 1.6, 1.9, 1.5, 2.9). AI-HOUSE and MAIN-LOUNGE slots reloaded in the window are ordinary core restocking, which the file does not count as a violation.
   - The snapshot cannot show that a fill-rule change did not reach AI-HOUSE or MAIN-LOUNGE, for the same reason as criterion 1.

3. **No other running experiment touches the slice: met.**
   - `swarm/experiments/` holds E-001, E-002 and E-003 only. E-001 and E-002 are closed with verdicts (`swarm/audits/V-E-001.md`, `V-E-002.md`).
   - The 00142 marketing table lists only the day-21 MAIN-LOUNGE campaign, so no campaign touches AI-LOUNGE.

## Mismatch

- **Criterion 1 is unmet and cannot be verified from ground truth.** The fill rule that the change uses is absent from the snapshot, so the change cannot be confirmed on every AI-LOUNGE unit, and it cannot be ruled out on the control units.
- **The before-state snapshot (day 112, before Start on day 113) is missing from the set.** The comparison as specified cannot be run literally.
- Notes, not criteria:
  - The `Applied` line's gummy top-up of 11 on SNACK A2 does not match the depot draw recorded in the earlier checks (8 left the depot). Not a criterion.
  - Cash, the EUR 144 pre-purchase guardrail, and the cost claims are not checked here; the system measures them.
  - The log (D128, D139) states that the operator has no tool to set a fill rule and that the change it made was the restock itself. That is the orchestrator's statement, not evidence, but it is consistent with the gap in the snapshot.
  - Crisps depot stock falling to zero with no crisps slot loaded is an unexplained core movement. Not an E-003 criterion.

- Restore `swarm/snapshots/00112.md` (day 112) to the set so the before/after comparison can be run as specified.
