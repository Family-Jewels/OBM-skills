# D-012 diagnosis, day 74: future-dated-quote-record (from P-011)

**Walk-down.** cash_gain_7 and cash are routine variation (charts.md). Guardrail cash >= 120 is ok (4196.52). No measure moved because of this fault. It is a record-integrity fault.

**Pinpoint.** On day 70 the worker wrote a "re-quote, day 71 (valid_through 77)" section and an "Ordered on day 71" line into swarm/log/T-0002.md before day 71 happened. The day-71 log then records a check and an order at the same prices. The day-70 log also states 345 minutes worked; P-011 read 305 from the clock.

**Maintained by.** The order gate (operator.md rule 18) checks only that valid_through_day is later than today. It does not check that the row is dated today or came from that day's check_offers. A pre-filled row passes the gate at no cost. The real first-step re-quote costs 25 minutes, and nothing downstream flags a future-dated row.

**Cause.** Environment, information: the gate's test is under-specified (the row's date is not checked), so records are written from the plan, not from observation. Worker: it filled the gate's expected row in advance. The minutes mismatch is the same pattern: the log states planned costs, not the clock.

**What would change (controls).** The gate should require a row dated today, sourced from that day's check_offers output. Log minutes must use the clock figure. A count of future-dated rows, target 0, would show whether it holds.

**Open.** Whether day 71's check returned the pre-written prices. The day-71 harness output, compared with T-0002.md, would settle it.
